## PRD

Build the backend extraction core for the Clinical Proof Mode pilot: turn a synthetic patient transcript into a list of `ClinicalClaim` objects with evidence spans, `extractionType` grading (Appendix A.1), rule-based safety screening (§8.7), red-flag detection (§8.6), and follow-up question generation (§8.5). Persist to a single SQLite `claims` table. Expose four endpoints: `POST /analyze`, `POST /review-claim`, `POST /precompute`, `GET /analyze/cached/{transcript_id}`. **On day 1, land the canonical claim-object schema directly on `clinical-proofing` and commit a root `Makefile`** so wt/02 and wt/03 can branch from a base that already has the schema visible.

## Day 2-3 — Implementation (TDD: tests first)

Implement modules in this order (each behind a failing test):

1. `app/core/evidence.py` — `locate_evidence(claim_text: str, raw_text: str) -> tuple[int, int]` returns `(start, end)` or raises `EvidenceNotFound`. Reject any claim whose `evidenceText` is not an exact substring of `rawText`.
2. Verify `app/rules/blocked_advice.py` covers all categories in §8.7.
3. `app/core/safety.py` — `screen_output(input, candidate_text, has_red_flags)` returns `SafetyBlock` or `None`. **100% line + branch coverage.** One regression test per category in `BLOCKED_CATEGORIES`.
4. `app/rules/red_flag_rules.py` — `match_red_flags(raw_text)` returns `list[(rule_key, start, end)]`. Cover all 8 vomiting + 5 medication red-flag rules from §8.6.
5. `app/core/extraction.py` — single Anthropic Claude call. Use the **claude-api skill** with prompt caching:
   - System prompt is **cached**: extraction instructions + 3 few-shot examples (one direct, one interpretation, one patientConcern downgrade per §17.3).
   - Variable input is the transcript only.
   - LLM self-classifies `extractionType` in its structured output.
   - Validate with content-word-overlap heuristic against the evidence span; if overlap < 0.5, force `extractionType="interpretation"` regardless of LLM label.
   - On malformed JSON: retry once with a "your previous response was malformed" appendix (same cached system prompt — cache hit preserved). If still bad, raise (the endpoint returns 502).
   - **`MIN_CACHE_TOKENS_BY_MODEL` constant.** `{"claude-sonnet-4-6": 1024, "claude-opus-4-7": 1024, "claude-haiku-4-5": 2048}`. On startup, assert `count_tokens(cached_block) >= MIN_CACHE_TOKENS_BY_MODEL[client.model_id]`. Fail loud if short — pad with additional style/wording examples. **The Anthropic cache silently no-ops below the model-specific threshold; this assertion is the only thing standing between you and a silently-broken cache.**
   - **`PROMPT_VERSION_HASH`.** `sha256` of the full cached system-prompt block (instructions + few-shot examples). Computed at module-load time, exposed as `app.core.extraction.PROMPT_VERSION_HASH`. Used as part of the precompute cache key.
6. `app/core/follow_up.py` — generate prioritized follow-up questions from `missingInfo[]`. Priority rules per §8.5.
7. **`app/core/dedup.py`** — `dedup_claims(claims: list[ClinicalClaim]) -> list[ClinicalClaim]`. For each `(eventType, evidence_span_overlap > 50%)` cluster, keep the highest-confidence claim, drop others. Log dropped count to stderr (no DB write for v1). Runs **before** safety screen and persistence.
8. `app/storage/repository.py` + SQLite `claims` table per pilot.md §6.1.7. Single table, no Alembic migrations. DB path from `CLAIMS_DB_PATH` env var, defaults to `.data/claims.db`. Schema includes `prompt_version_hash`, `model_id`, `escalation_message`, and a composite index on `(input_id, prompt_version_hash, model_id)` for cache lookup.
9. `app/api/analyze.py` — wire `POST /analyze`. Pipeline: input → extraction → evidence check → **dedup** → safety screen → red-flag rules → response (claims + `red_flag_only_spans_json` + `escalation_message` if urgent — **all response-level fields**) → persist → return `AnalyzeResponse`.
10. `app/api/review.py` — wire `POST /review-claim`. Load claim → apply doctor action → if edit, set `originalClaimText` (only on first edit; subsequent edits do not overwrite) and store `doctorEditOrigin` → persist → return `ReviewClaimResponse`. **Critical: `escalation_message` and `red_flag_only_spans_json` are response-level fields. `/review-claim` MUST NOT modify them.** The sticky-escalation rule (pilot.md §2) requires that doctor actions on a claim never retract the response-level escalation payload.
11. **Precompute pipeline.** New module `app/core/precompute.py`. Endpoints:
    - `POST /precompute` — body: `[{transcript_id, raw_text, context?}]`. Runs the full pipeline for each, persists with cache key `(input_id, prompt_version_hash, model_id)`. Returns count of cached + count of refreshed.
    - `GET /analyze/cached/{transcript_id}` — looks up by `(input_id=transcript_id, prompt_version_hash=PROMPT_VERSION_HASH, model_id=client.model_id)`. Returns 200 + `AnalyzeResponse` on hit, 404 on miss.
    - `make precompute-fresh` truncates the `claims` table before running precompute (forces a fresh batch). `make precompute` is idempotent — only re-runs entries that miss the cache.

## Hard rules (no exceptions)

- **No claim emitted without a verified evidence span.** Drop the claim or set `riskLevel="needs-review"` and surface it with a `displayWarning`.
- **Med-change advice always blocked** with the safe replacement from `app/rules/blocked_advice.py:SAFE_REPLACEMENTS`.
- **Diagnosis inference (§17.3) downgrades** to `eventType="patientConcern"` and `safetyStatus="diagnosisNotConfirmed"`.
- **Urgent-risk transcripts (§13.4)** always produce a claim AND attach the §13.4 escalation message **verbatim** from `app/rules/risk_messages.py`. The LLM never authors this string.
- **Doctor edit preserves `originalClaimText`** verbatim (only set on first edit) and stores `doctorEditOrigin`.
- **Sticky escalations.** `escalation_message` (response-level) and `red_flag_only_spans_json` (response-level) are NOT modified by `/review-claim`. Doctor accept/edit/reject only touches the claim row; the response-level escalation payload is immutable after `/analyze`. Bar #6 and bar #7 in the eval harness read from these response-level fields.
- **Dedup before safety/persistence.** Two claims with same eventType + overlapping evidence (>50%) collapse to higher-confidence one BEFORE `screen_output` runs.
- **The LLM never authors final patient-facing text** in safety-blocked categories. The blocker authors all replacement language.

## Required tests (in addition to per-module unit tests)

1. **Cache-hit integration test (H3).** Mock the Anthropic client. Assert `cache_control` set on the system block. Assert `usage.cache_read_input_tokens > 0` on the second call against an identical input.
2. **Cache-token threshold test (C2).** Verify `MIN_CACHE_TOKENS_BY_MODEL` assertion fires when the cached block is artificially shrunk below the per-model threshold. Test all three models in `MIN_CACHE_TOKENS_BY_MODEL`.
3. **Evidence-span integrity property test (M3).** For 50 random shaped inputs (use `hypothesis` or table-driven), run extraction with a stubbed LLM that returns shaped output, assert every persisted claim satisfies `claim.evidence_text == claim.raw_text[claim.evidence_start:claim.evidence_end]`.
4. **Sticky escalation test (H5).** Create an urgent-risk input → `/analyze` → reject the urgent claim via `/review-claim`. Assert response-level `escalation_message` and `red_flag_only_spans_json` are **unchanged** across both states. Repeat for an edit-downgrade ("fainted" → "lightheaded").
5. **Dedup test (M2a).** Inject 3 candidate claims with same eventType + overlapping spans + different confidences. Assert only the highest-confidence claim survives.
6. **Prompt-version cache invalidation test (C3).** Precompute against transcript T → manually mutate `PROMPT_VERSION_HASH` (or the cached prompt) → `GET /analyze/cached/T` returns 404. `POST /precompute` against T re-populates with the new hash.
7. **Safety regression suite (§8.7).** One regression test per category in `BLOCKED_CATEGORIES`. Lives in `tests/safety/`.
