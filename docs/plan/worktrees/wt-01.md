## PRD

Build the backend extraction core for the Clinical Proof Mode pilot: turn a synthetic patient transcript into a list of `ClinicalClaim` objects with evidence spans, `extractionType` grading (Appendix A.1), rule-based safety screening (§8.7), red-flag detection (§8.6), and follow-up question generation (§8.5). Persist to a single SQLite `claims` table. Expose `POST /analyze` and `POST /review-claim`. **Publish the canonical claim-object schema as TypeScript types on day 1** — the Phase 1 gate that unblocks wt/02 and wt/03.

## Day 1 — Schema gate (sequential, blocks wt/02 and wt/03)

1. Write `packages/shared/types.ts` with: `ClinicalClaim`, `Evidence`, `RiskAssessment`, `SafetyBlock`, `FollowUpQuestion`, `DoctorAction`, `DoctorReviewStatus`, `ExtractionType` (`"direct" | "interpretation"`), `DoctorEditOrigin` (`"minor_wording" | "correction" | "external_knowledge_override"`), `EventType`, `RiskLevel`, `SafetyStatus`. **Single source of truth.**
2. Extend `app/models/claim.py` and `app/models/enums.py` with `extractionType` and `doctorEditOrigin` (and `RiskLevel.NEEDS_REVIEW` if not present). Pydantic field names match TS field names byte-for-byte.
3. Write `docs/eval/fixtures/sample-claims.json` — 3-5 sample claim objects covering: a `direct` extraction, an `interpretation` extraction, a `medicationAdviceBlocked` claim, an urgent-risk claim. Used by wt/02 and wt/03 in Phase 2.
4. Write `scripts/check-schema-drift.py` — fails if Pydantic field set diverges from TS field set. Lightweight: parse both, compare key sets and enum values.
5. Tag commit `pilot/schema-v1` and announce in PR. **wt/02 and wt/03 do not start until this tag exists.**

## Day 2-3 — Implementation (TDD: tests first)

Implement modules in this order (each behind a failing test):

1. `app/core/evidence.py` — `locate_evidence(claim_text: str, raw_text: str) -> tuple[int, int]` returns `(start, end)` or raises `EvidenceNotFound`. Reject any claim whose `evidenceText` is not an exact substring of `rawText`.
2. Verify `app/rules/blocked_advice.py` covers all categories in §8.7.
3. `app/core/safety.py` — `screen_output(input, candidate_text, has_red_flags)` returns `SafetyBlock` or `None`. **100% line + branch coverage required.** One regression test per category in `BLOCKED_CATEGORIES`.
4. `app/rules/red_flag_rules.py` — `match_red_flags(raw_text)` returns `list[(rule_key, start, end)]`. Cover all 8 vomiting + 5 medication red-flag rules from §8.6.
5. `app/core/extraction.py` — single Anthropic Claude call. Use the **claude-api skill** with prompt caching:
   - System prompt is **cached**: extraction instructions + 3 few-shot examples (one direct, one interpretation, one patientConcern downgrade per §17.3).
   - Variable input is the transcript only.
   - Output is structured JSON parsed into `ClinicalClaim[]` with the LLM self-classifying `extractionType`.
   - **Validate** with a content-word-overlap heuristic against the evidence span. If the LLM said `direct` but overlap < 0.5, force `extractionType="interpretation"`. The heuristic is a defense, not the source of truth — it's there to catch LLMs over-claiming directness.
   - On malformed JSON: retry once with a "your previous response was malformed" appendix; if still bad, raise (the endpoint returns 502).
6. `app/core/follow_up.py` — generate prioritized follow-up questions from `missingInfo[]`. Priority rules per §8.5.
7. `app/storage/repository.py` + SQLite `claims` table per pilot.md §6.1.7. Single table, no migrations. DB path from `CLAIMS_DB_PATH` env var, defaults to `.data/claims.db`.
8. `app/api/analyze.py` — wire `POST /analyze`. Pipeline: input → extraction → evidence check → safety screen → red-flag rules → claim list (red-flag-only spans tagged separately on the response payload, NOT inside individual claims) → persist → return `AnalyzeResponse`.
9. `app/api/review.py` — wire `POST /review-claim`. Load claim → apply doctor action → if edit, set `originalClaimText` (only on first edit; subsequent edits do not overwrite) and store `doctorEditOrigin` → persist → return `ReviewClaimResponse`.

## Hard rules (no exceptions)

- **No claim emitted without a verified evidence span.** Drop the claim or set `riskLevel="needs-review"` and surface it with a `displayWarning`.
- **Med-change advice always blocked** with the safe replacement from `app/rules/blocked_advice.py:SAFE_REPLACEMENTS`.
- **Diagnosis inference (§17.3) downgrades** to `eventType="patientConcern"` and `safetyStatus="diagnosisNotConfirmed"`.
- **Urgent-risk transcripts (§13.4)** always produce a claim AND attach the §13.4 escalation message **verbatim** from `app/rules/risk_messages.py`. The LLM never authors this string.
- **Doctor edit preserves `originalClaimText`** verbatim (only set on first edit) and stores `doctorEditOrigin`.
- **The LLM never authors final patient-facing text** in the safety-blocked categories. The blocker authors all replacement language.
