## PRD

Build the backend extraction core for the Clinical Proof Mode pilot: turn a synthetic patient transcript into an `AnalyzeResponse` containing a list of `ClinicalClaim` objects (with evidence spans, `extractionType` grading per Appendix A.1, rule-based safety screening per §8.7) plus response-level `escalationMessage` and `redFlagOnlySpans` fields. Persist to two SQLite tables: `analyze_responses` (immutable response-level data) and `claims` (mutable claim-level data). Expose four endpoints: `POST /analyze`, `POST /review-claim`, `POST /precompute`, `GET /analyze/cached/{transcript_id}`. **On day 1, land the canonical claim-object schema directly on `clinical-proofing` and commit a root `Makefile`** so wt/02 and wt/03 can branch from a base that already has the schema visible.

## Day 2-3 — Implementation (TDD: tests first)

Implement modules in this order (each behind a failing test):

1. `app/core/evidence.py` — `locate_evidence(claim_text: str, raw_text: str) -> tuple[int, int]` returns `(start, end)` or raises `EvidenceNotFound`. Reject any claim whose `evidenceText` is not an exact substring of `rawText`.
2. Verify `app/rules/blocked_advice.py` covers all categories in §8.7.
3. `app/core/safety.py` — `screen_output(input, candidate_text, has_red_flags)` returns `SafetyBlock` or `None`. **100% line + branch coverage.** One regression test per category in `BLOCKED_CATEGORIES`.
4. `app/rules/red_flag_rules.py` — `match_red_flags(raw_text)` returns `list[(rule_key, start, end)]`. Cover all 8 vomiting + 5 medication red-flag rules from §8.6.
5. `app/core/extraction.py` — single Anthropic Claude call. Use the **claude-api skill** with prompt caching:
   - System prompt is **cached**: extraction instructions + 3 few-shot examples (one direct, one interpretation, one patientConcern downgrade per §17.3).
   - Variable input is the transcript only.
   - LLM self-classifies `extractionType` in its structured output.
   - Validate with content-word-overlap heuristic against the evidence span; if overlap < 0.5, force `extractionType="interpretation"` regardless of LLM label.
   - On malformed JSON: retry once with a "your previous response was malformed" appendix (same cached system prompt — cache hit preserved). If still bad, raise (the endpoint returns 502).
   - **`MIN_CACHE_TOKENS_BY_MODEL` constant.** `{"claude-sonnet-4-6": 1024, "claude-opus-4-7": 1024, "claude-haiku-4-5": 2048}`. **Token counting via Anthropic SDK's `client.messages.count_tokens()` (post-review H7) — `tiktoken` is wrong for Claude.** On startup (module-import time, **before FastAPI binds to a port**), assert `client.messages.count_tokens(<cached_block>) >= MIN_CACHE_TOKENS_BY_MODEL[client.model_id]`. Fail loud if short — pad with additional style/wording examples. The Anthropic cache silently no-ops below the model-specific threshold; this assertion is the only thing standing between you and a silently-broken cache.
   - **`PROMPT_VERSION_HASH`.** `sha256` of the full cached system-prompt block (instructions + few-shot examples). Computed at module-load time, exposed as `app.core.extraction.PROMPT_VERSION_HASH`. Used as part of the `analyze_responses` cache key.
6. `app/core/follow_up.py` — generate prioritized follow-up questions from `missingInfo[]`. Priority rules per §8.5.
7. **`app/core/dedup.py`** — `dedup_claims(claims: list[ClinicalClaim]) -> list[ClinicalClaim]`. For each `(eventType, evidence_span_overlap > 50%)` cluster, keep the highest-confidence claim, drop others. Log dropped count to stderr (no DB write for v1). Runs **before** safety screen and persistence.
8. `app/storage/repository.py` + **two SQLite tables** per pilot.md §6.1.7. No Alembic migrations. DB path from `CLAIMS_DB_PATH` env var, defaults to `.data/claims.db`. The `analyze_responses` table holds response-level data (one row per `/analyze` call, immutable after creation). The `claims` table holds claim-level data (zero or more rows per response, mutable via `/review-claim`). Composite key on both tables: `(input_id, prompt_version_hash, model_id)`. `claims` references `analyze_responses` via foreign key.
9. `app/api/analyze.py` — wire `POST /analyze`. Pipeline: input → extraction → evidence check → **dedup** → safety screen → red-flag rules → assemble `AnalyzeResponse` (claims + `escalationMessage` + `redFlagOnlySpans`) → **persist: write one row to `analyze_responses` (always, even when zero claims) and N rows to `claims`** → return `AnalyzeResponse`.
10. `app/api/review.py` — wire `POST /review-claim`. Load claim from `claims` → apply doctor action → if edit, set `originalClaimText` (only on first edit; subsequent edits do not overwrite) and store `doctorEditOrigin` → persist to `claims` → return `ReviewClaimResponse`. **`/review-claim` MUST NOT touch `analyze_responses`.** The structural separation enforces the sticky-escalation rule by design — there is no path from doctor actions to response-level escalation fields.
11. **Precompute pipeline.** New module `app/core/precompute.py`. Endpoints:
    - `POST /precompute` — body: `[{transcript_id, raw_text, context?}]`. Runs the full pipeline for each, writes one row per transcript to `analyze_responses` (regardless of claim count) plus N rows to `claims`. Returns counts of cached + refreshed.
    - `GET /analyze/cached/{transcript_id}` — looks up the `analyze_responses` row by `(input_id=transcript_id, prompt_version_hash=PROMPT_VERSION_HASH, model_id=client.model_id)`. JOINs `claims` for the claim list. Returns 200 with `{claims: [...], escalationMessage, redFlagOnlySpans}` on hit (zero-claim cases return `claims: []` with the escalation payload intact). Returns **404 only when the response itself was never computed** — critical distinction for the demo's central urgent-risk moment.
    - `make precompute-fresh` — **destructive (post-review M6)**. Truncates BOTH `analyze_responses` AND `claims` before re-running. Nukes any demo state from manual reviewer clicks. `make precompute` is idempotent — only re-runs entries that miss the cache.

## Hard rules (no exceptions)

- **No claim emitted without a verified evidence span.** Drop the claim or set `riskLevel="needs-review"` and surface it with a `displayWarning`.
- **Med-change advice always blocked** with the safe replacement from `app/rules/blocked_advice.py:SAFE_REPLACEMENTS`.
- **Diagnosis inference (§17.3) downgrades** to `eventType="patientConcern"` and `safetyStatus="diagnosisNotConfirmed"`.
- **Urgent-risk transcripts (§13.4)** always produce a populated `analyze_responses.escalation_message` (verbatim from `app/rules/risk_messages.py`). The LLM never authors this string. Even when zero claims are emitted, the urgent-risk escalation must persist on the response row.
- **Doctor edit preserves `originalClaimText`** verbatim (only set on first edit) and stores `doctorEditOrigin`.
- **Sticky escalations — structural.** `analyze_responses` is **immutable** after creation. `/review-claim` operates on `claims` only; there is no code path from doctor actions to `analyze_responses` rows. Bar #6 reads `analyze_responses.escalation_message`. Bar #7 reads `analyze_responses.red_flag_only_spans_json`.
- **Dedup before safety/persistence.** Two claims with same eventType + overlapping evidence (>50%) collapse to higher-confidence one BEFORE `screen_output` runs.
- **The LLM never authors final patient-facing text** in safety-blocked categories. The blocker authors all replacement language.
- **Token counting via Anthropic SDK only.** `count_tokens()` calls go through `client.messages.count_tokens()`. No `tiktoken`, no character-length proxies. The assertion fires at module import, before FastAPI binds to a port.

## Required tests (in addition to per-module unit tests)

1. **Cache-hit integration test (H3).** Mock the Anthropic client. Assert `cache_control` set on the system block. Assert `usage.cache_read_input_tokens > 0` on the second call against an identical input.
2. **Cache-token threshold test (C2 + H7).** Mock `client.messages.count_tokens()` to return a value below the model's threshold; assert the startup assertion raises BEFORE the FastAPI app binds to a port. Test all three models in `MIN_CACHE_TOKENS_BY_MODEL`.
3. **Evidence-span integrity property test (M3).** For 50 random shaped inputs (use `hypothesis` or table-driven), run extraction with a stubbed LLM that returns shaped output, assert every persisted claim satisfies `claim.evidence_text == claim.raw_text[claim.evidence_start:claim.evidence_end]`.
4. **Sticky escalation test (H5 + C4).** Create an urgent-risk input → `/analyze` → reject the urgent claim via `/review-claim`. Read `GET /analyze/cached/{id}` after the rejection — assert `escalationMessage` and `redFlagOnlySpans` in the response are **byte-identical** to the original `/analyze` response. Repeat for an edit-downgrade ("fainted" → "lightheaded"). Assert no row in `analyze_responses` was modified between the two states (verify by querying `created_at` — should be the original timestamp).
5. **Zero-claim escalation persistence test (C4).** Create an urgent-risk transcript that the LLM extracts zero claims from (force this with a stubbed LLM returning `[]`). Assert `analyze_responses` has one row with non-null `escalation_message`. Assert `GET /analyze/cached/{id}` returns 200 with `claims: []` and the escalation payload intact (NOT 404).
6. **Dedup test (M2a).** Inject 3 candidate claims with same eventType + overlapping spans + different confidences. Assert only the highest-confidence claim survives.
7. **Prompt-version cache invalidation test (C3).** Precompute against transcript T → manually mutate `PROMPT_VERSION_HASH` (or the cached prompt) → `GET /analyze/cached/T` returns 404. `POST /precompute` against T re-populates `analyze_responses` with the new hash.
8. **`make precompute-fresh` destructive test (M6).** Populate `analyze_responses` and `claims`. Manually update a claim's `doctor_review_status` to simulate reviewer clicks. Run `make precompute-fresh`. Assert both tables are truncated and re-populated; the manual click state is gone.
9. **Safety regression suite (§8.7).** One regression test per category in `BLOCKED_CATEGORIES`. Lives in `tests/safety/`.
